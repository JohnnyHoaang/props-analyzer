# Player Images Setup Guide

This guide walks you through adding player images to your database and uploading them to Supabase S3.

## Overview

The CSV file `apps/worker/player-images.csv` contains ESPN image URLs for all players. You have two options:

1. **Fast Option**: Store ESPN URLs directly in the database
2. **Recommended Option**: Download images and host them on your Supabase S3

## Prerequisites

- Supabase project set up with credentials in `.env`
- `pnpm` installed
- Node 18+

## Step 1: Apply the Database Migration

This creates the `players.image_url` column:

```bash
pnpm exec supabase db push
```

Or manually run the SQL in your Supabase dashboard:
```sql
ALTER TABLE players ADD COLUMN IF NOT EXISTS image_url text;
```

## Step 2: Choose Your Approach

### Option A: Store ESPN URLs (Fast)

```bash
cd apps/worker
pnpm run import-player-images
```

✓ Quick (< 1 minute)
✗ Depends on ESPN maintaining the URLs

### Option B: Upload to Supabase S3 (Recommended)

#### 2a. Create the S3 bucket

Go to your [Supabase Dashboard](https://supabase.com/dashboard):
1. Select your project
2. Go to **Storage** (left sidebar)
3. Click **Create a new bucket**
4. Name it `nba-assets`
5. Choose privacy level (public recommended for convenience)
6. Click **Create**

#### 2b. Upload images

```bash
cd apps/worker
pnpm run upload-images-s3
```

This script:
- Downloads ~575 ESPN images
- Uploads each to your S3 bucket
- Updates the database with S3 URLs
- Takes ~10-20 minutes depending on your connection
- Is idempotent (safe to re-run)

**Expected output:**
```
Processing 575 player images...
Uploading to Supabase bucket: nba-assets

Downloading image for A.J. Green (38017733)...
  Uploading to S3...
  Updating database...
  ✓ Complete: https://...storage.supabase.co/storage/v1/object/public/nba-assets/38017733.png
  
...
```

## Verifying the Setup

Check that images were imported:

```bash
# In Supabase SQL editor:
SELECT COUNT(*) FROM players WHERE image_url IS NOT NULL;

-- Or to see some examples:
SELECT id, full_name, image_url FROM players 
WHERE image_url IS NOT NULL 
LIMIT 5;
```

You should see URLs like:
- **ESPN option**: `https://a.espncdn.com/combiner/i?img=/i/headshots/nba/players/full/4397475.png&w=350&h=254`
- **S3 option**: `https://{project-id}.storage.supabase.co/storage/v1/object/public/nba-assets/38017733.png`

## Troubleshooting

**"SUPABASE_URL and SUPABASE_SECRET_KEY must be set"**
- Check that `.env` has both variables set
- Example:
  ```
  SUPABASE_URL=https://xxxxx.supabase.co
  SUPABASE_SECRET_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
  ```

**"DB update failed: 400"**
- Migration not applied: run `pnpm exec supabase db push`
- Player IDs don't match: verify CSV has correct player IDs

**"Upload failed: 401"**
- Invalid service key in `.env`
- Check your Supabase dashboard for the correct `SUPABASE_SECRET_KEY`

**"HTTP 404 when downloading images"**
- Some ESPN URLs may be expired (this is normal)
- The script continues with other players and logs failures

**Images uploaded but DB shows NULL**
- Check Supabase logs for PATCH errors
- Verify `nba-assets` bucket is accessible

## Next Steps

Once images are loaded, you can:
- Use the URLs in your frontend to display player headshots
- Reference `players.image_url` in queries
- Cache images for faster load times
- Generate responsive image variants if needed

## Notes

- The CSV was generated by `apps/worker/assign-player-images.mjs`
- The upload script uses a concurrency limit of 4 to avoid rate limits
- All operations are idempotent (safe to re-run)
- Images are stored as PNG in Supabase S3 with player ID as the filename
